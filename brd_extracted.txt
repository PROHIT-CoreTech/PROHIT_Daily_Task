2. Executive Summary
PROHIT Daily Task is a generic productivity and task-management platform, positioned similarly to TickTick, built to serve individuals, students, freelancers, and teams from launch. The platform is architected around a single reusable Core Engine so that, once validated with a general audience, vertical-specific business modules (CA Practice Management, Coaching Management, Clinic Management, Real Estate Management, Agency Management, and a Custom Business Workspace for any other business type) can be layered on top without rebuilding the core product.
The product will be self-developed by the founder within a budget of ₹30,000–40,000 covering tools, infrastructure, and hosting costs, using an AI-assisted development workflow on a Next.js/Node/MongoDB stack. Monetization follows a feature-wise subscription model — Free, Pro, and Team tiers for the generic product, with vertical modules and an AI add-on sold as separate paid layers on top.
Distinct branding (Charcoal Navy and Emerald Teal palette, and original feature nomenclature such as "Flow Board" and "Deep Work Sprint") has been deliberately chosen to avoid visual or naming overlap with TickTick and other market incumbents.
3. Business Objectives
Launch a low-cost, self-built MVP that validates a generic task-management product with real users before investing in vertical-specific development.
Build a reusable Core Engine architecture so future vertical modules (CA, Coaching, Clinic, Real Estate, Agency, and others) can be added as configuration/data, not code rewrites.
Establish a feature-wise, modular subscription model that scales revenue per workspace/user rather than relying on a single flat price.
Capture a broad top-of-funnel user base — individuals, students, and small teams — to build brand recognition ahead of monetizing higher-value business verticals.
Keep the vertical module list open-ended, avoiding a hardcoded set of business types, so new industries can be onboarded without re-architecture.
Differentiate PROHIT's naming, visual design, and color palette clearly from TickTick and other direct competitors to reduce trade-dress/copyright risk and build independent brand identity.
4. Target Users & Market Segments
4.1 Primary Segments (Launch Phase)
Individual professionals and freelancers managing personal task lists and schedules.
College, Masters, and degree students — assignment/exam tracking, study-group coordination, focus sessions.
Small teams needing shared task boards and basic collaboration (Team Workspace).
4.2 Secondary Segments (Vertical Modules — Later Phases)
CA / accounting firms — client compliance and task workflows.
Coaching institutes — batch, session, and student management.
Clinics — patient and appointment-linked task workflows.
Real estate and agency businesses — project/lead-linked task workflows.
Any other business type via the open-ended Custom Business Workspace module.
5. Scope
5.1 In Scope — Phase 1 (MVP)
User authentication and Workspace creation (Personal / Team / Business types).
Core Task Engine: create, edit, complete, subtasks, priority, due dates, tags.
Lists / Projects with recurring task support.
Reminders (email-based for V1).
Calendar view — month and week.
Flow Board — Kanban-style visual task board (To Do / In Progress / Done, customizable columns).
Dashboard with completion %, overdue tasks, and basic filters.
Subscription and billing integration (Razorpay Subscriptions) with Free, Pro, and Team tiers.
Entitlement-based feature gating architecture (module/feature flags per workspace).
Responsive Web App with PWA support (installable, offline-capable, home-screen icon).
5.2 Out of Scope — Phase 1
Native mobile applications (iOS/Android via React Native) — planned for a later phase once paid usage validates demand.
Deep Work Sprint (Pomodoro-style focus timer) — planned for a fast-follow V1.1 release.
AI Assistant features (voice-to-task, AI daily planning, AI summary) — to be released later as a separate paid add-on, not bundled into Pro.
Vertical business modules (CA, Coaching, Clinic, Real Estate, Agency) — planned for later phases once the generic core is validated.
WhatsApp integration, n8n-based automation workflows, and third-party calendar sync (Google/Outlook) — future phases.

8.2 Data & Entitlement Model
Subscription and entitlement data is kept in dedicated collections separate from core Workspace data, to avoid write contention from frequent Razorpay webhook updates against a document also read on every request.
workspaces — workspace identity, owner, and type (personal / team / business).
subscriptions — plan, status, active modules, renewal date, keyed by workspaceId.
entitlements_cache — denormalized feature flags per workspace for fast read access on every request.
modules — data-driven definitions of each vertical module (field schema, task/client label overrides, pricing), enabling new verticals to be added without core code changes.
8.3 System Architecture Overview
The system follows a layered structure: a shared Core Engine (Task, Project, User, Team, Calendar, Reminder, Notification, Attachment, Comment, Billing) sits beneath three Workspace types (Personal, Team, Business). Business Workspaces can attach one or more Vertical Modules as paid add-ons, including an open-ended Custom Business Workspace for industries not yet formally modeled. A parallel Subscription & Entitlement Flow governs plan selection, payment processing via Razorpay, webhook-driven entitlement updates, and the resulting feature unlocks in the application.

11. Platform Strategy
Phase 1 ships as a responsive Next.js Web App with Progressive Web App (PWA) support — installable to a mobile home screen, with basic offline caching — rather than a native mobile app.
Business-vertical users (CA firm staff, clinic front-desk, coaching admin) primarily work from desktop during office hours — a web-first approach serves this segment directly.
Individual and student users primarily use mobile — covered adequately by the installable PWA experience.
A native React Native app is deferred to Phase 4, once paying users validate which mobile-specific features are actually needed, avoiding premature app-store development cost and review delays.
